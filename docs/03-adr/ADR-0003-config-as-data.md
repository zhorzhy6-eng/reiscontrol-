# ADR-0003. Config-as-data с иммутабельным snapshot на рейс

**Статус:** Принято
**Дата:** 02.10.2026
**Заменяет:** —
**Заменён на:** —

---

## Контекст

ТЗ п. 6.5 требует:
- чек-листы, ракурсы, типы событий, список документов и правила завершения задаются конфигурацией, а не кодом;
- правка не должна требовать релиза приложения;
- изменение в середине рейса не должно ломать уже начатые рейсы;
- должны быть разные конфигурации для разных типов рейсов, типов грузов и клиентов.

ТЗ п. 6.2 требует:
- добавлять новые типы событий, чек-листов, документов и ракурсов **без переписывания системы**;
- менять состав и порядок шагов чек-листа **без выпуска нового релиза приложения**;
- отключать новую функцию **без выпуска нового релиза**.

---

## Решение

- Типы событий, чек-листы, ракурсы, документы, правила завершения — **строки в БД**.
- При старте рейса фиксируется `config_snapshot_id` — **иммутабельный снимок** конфигурации.
- Рейс работает по своему снимку. Правки в шаблоне на него не влияют.
- Новые рейсы получают новую версию шаблона.
- Приложение — **интерпретатор** ограниченного набора примитивов.

### Примитивы (стартовый набор)

| Примитив | Что делает |
|---|---|
| `photo_set` | набор фото по ракурсам |
| `document_set` | набор документов |
| `number` | числовой ввод |
| `text` | текстовый ввод |
| `confirm` | подтверждение |
| `signature` | подпись |
| `geo_only` | только координаты и время |

**Новый тип события** = строка в `event_types` + привязка к одному из примитивов. **Новый ракурс** = новая строка в `checklist_steps`.

### Галерея в примитиве `photo_set`

По умолчанию **галерея разрешена** как альтернативный способ загрузки фото. Водитель может:
- сфотографировать через камеру (основной способ);
- выбрать фото из галереи (альтернативный способ).

Оба варианта допустимы. Приложение **не требует** указывать причину. В метаданных фиксируется только источник: `camera` / `gallery`.

**Галерея отключается через конфиг** (`allow_gallery: false`) — если заказчик решит ограничить.

---

## Обоснование

- Без снимка логист «на ходу» сломает водителю сдачу фото.
- Без config-as-data невозможно выполнить п. 6.2 и п. 6.5 ТЗ.
- Ограниченный набор примитивов (а не универсальный конструктор) — прагматизм пилота.
- Галерея разрешена — практическая необходимость (сломанная камера, съёмка на другое устройство).

---

## Последствия

- Появляется **конфигуратор в веб-кабинете** — обязанность логиста, не разработчика.
- Каждый рейс хранит ссылку на снимок, а не на «текущий» шаблон.
- Новые рейсы получают новую версию, активные — продолжают по прежней.
- В метаданных фото фиксируется источник: `camera` / `gallery`.
- Логист видит иконку источника рядом с фото.

---

## Влияние на обновляемость

**Не требует релиза APK/IPA:**
- Добавление/удаление ракурса.
- Изменение порядка шагов.
- Добавление нового типа события (если он использует существующий примитив).
- Добавление нового документа.
- Изменение правил завершения.
- Добавление нового типа груза (через справочник).
- Отключение функции через `feature_flags`.
- **Включение/отключение галереи** (`allow_gallery: true/false`).

**Требует релиза APK/IPA:**
- Добавление **нового примитива** (например, `video`).
- Изменение поведения существующего примитива.
- Изменение UI-интерпретации шага.

**Правило:** если новый элемент = комбинация существующих примитивов — без релиза. Если нужен новый примитив — с релизом.

## Открытые вопросы

1. Согласны ли с 7 примитивами? Нужны ли дополнительные на этапе 1?
   **Ответ:** Да, согласен с 7 примитивами.

2. Галерея разрешена?
   **Ответ:** Да. По умолчанию разрешена. Отключается через конфиг при необходимости.
