# ADR-0001. Выбор СУБД: PostgreSQL managed вместо YDB

**Статус:** Принято
**Дата:** 02.10.2026
**Заменяет:** —
**Заменён на:** —

---

## Контекст

ТЗ «Рейс-Контроль» v4.0 (п. 9) предлагает на выбор YDB serverless **или** PostgreSQL.

Проект имеет:
- много связанных данных (рейсы, события, вложения, конфигурация);
- потребность в аналитике и выгрузках (п. 7.2 ТЗ);
- требование п. 6.4 ТЗ о сопровождаемости силами команды, не участвовавшей в разработке;
- требование п. 7.2 о разграничении доступа по ролям и рейсам.

---

## Решение

Использовать **PostgreSQL managed** (Yandex Managed Service for PostgreSQL).

---

## Обоснование

- Массовая экспертиза на рынке — важно для передачи проекта по п. 6.4 и п. 17 ТЗ.
- Полноценный SQL, оконные функции, JSONB + GIN-индексы — нужны для аналитики и гибких полей.
- Привычные ORM (SQLAlchemy) и миграции (Alembic) — ускоряют разработку.
- Локальный запуск в Docker — упрощает тестирование.
- Разница в цене (~2 тыс ₽/мес) на порядок меньше стоимости недель, потерянных на непривычном стеке.

---

## Последствия

- Доступ к данным — только через репозитории, схема без вендор-специфики.
- При необходимости миграция на YDB или on-prem возможна без переписывания логики.
- Alembic обеспечивает миграции expand/contract (см. ADR-0008).

---

## Влияние на обновляемость

**Не требует релиза APK/IPA:**
- Смена СУБД — инфраструктурное изменение.
- Изменения схемы БД — через expand/contract, если API остаётся аддитивным.

**Требует релиза APK/IPA:**
- Ничего, если API не меняется.
