# Проект контракта `Event.payload`, версия 1

**Статус:** на согласовании. Не использовать как утверждённый API до решения.

`event_type_code` выбирается из снимка конфигурации рейса. Сервер находит
`event_types.primitive`, затем схему из `event_payload_schemas` по паре
`(event_type_code, payload_schema_version)`. Версия находится в поле
`Event.payload_schema_version` существующего OpenAPI; внутри `payload` она не
повторяется. Первый набор схем имеет версию `1`.

Существующие файлы `Project/docs/schemas/{photo_set,document_set,text,number,
confirm,signature,geo_only}.json` описывают **конфигурацию** примитивов. Ниже
предложен формат **факта**, который отправляет клиент. Коды в примерах берутся
из снимка, а не из списка в приложении.

## Формы payload

| Примитив | Обязательная форма `payload` | Проверка относительно снимка |
|---|---|---|
| `photo_set` | `{"photos":[{"step_code":"front_3_4","attachment_id":"<uuid>","source":"camera"}]}` | `step_code` существует; для обязательных шагов выполнены `min_photos`/`max_photos`; `source` совпадает с вложением; `gallery` допустима по `allow_gallery` и текущему feature flag. |
| `document_set` | `{"documents":[{"document_code":"ttn","attachment_id":"<uuid>"}]}` | `document_code` существует; обязательные документы представлены; для `pages: "multi"` допустимо несколько записей с одним кодом. |
| `text` | `{"value":"Т-123"}` | Строка соответствует `required`, `min_length`, `max_length`, `pattern` из конфигурации. |
| `number` | `{"value":123.5}` | Число соответствует `min`, `max`, `decimal` из конфигурации; `unit` берётся из неё. |
| `confirm` | `{"value":true}` | Подтверждение считается завершённым только при `true`. |
| `geo_only` | `{"point_id":"<uuid>"}` | Точка принадлежит рейсу; измерение и точность берутся из верхнеуровневых полей `Event` (`lat`, `lon`, `accuracy_m`, `location_source`). |
| `signature` | `{"attachment_id":"<uuid>","full_name":"Иван Иванов"}` | Вложение имеет `kind: signature`; `full_name` обязателен только при `require_full_name: true`. Это поле содержит ПДн и не попадает в логи. |

У `photo_set` и `document_set` массив может содержать несколько записей с одним
кодом в пределах ограничений снимка. Один `attachment_id` внутри события
используется только один раз. Для остальных примитивов допустимы только
указанные поля. Приложение может сохранить неполный `draft` локально, но
`POST /events` принимает лишь завершённый факт.

## Связи и приём

1. `step_code` ссылается на шаг фото в снимке рейса; `document_code` — на
   документ из того же снимка. Смена шаблона после старта рейса не меняет
   проверку уже начатого рейса.
2. Каждый `attachment_id` ссылается на `attachments.id` в состоянии `stored`,
   связан с тем же клиентским событием и доступен пользователю. Предлагаемый
   порядок загрузки: `attachments:init` с `owner_type: "event"` и
   `owner_id: client_event_id`, прямая загрузка, `:commit`, затем `POST /events`.
   Это позволяет загрузить файлы до появления серверного `events.id`.
3. Для `photo_set` сервер сравнивает `photos[].source` с `attachments.source`.
   Водяной знак проверяется по `attachments.watermark_meta` и политике снимка.
   Причина выбора галереи не передаётся.
4. Для `geo_only` `payload.point_id` должен совпадать с верхнеуровневым
   `Event.point_id`, если старый клиент отправляет оба поля. В следующей
   аддитивной версии можно оставить только один источник значения.
5. `client_event_id` создаётся как UUIDv7 на клиенте. Сервер обеспечивает
   уникальность пары `(client_event_id, device_id)`. Повтор того же тела
   возвращает прежний результат и не создаёт новое событие или уведомление;
   повтор с изменённым содержимым — конфликт. Точный HTTP-код для повтора
   согласуется отдельно, поскольку текущий OpenAPI указывает `409` для любого
   дубликата.

## Открытые пункты перед утверждением

- Подтвердить `signature.full_name`: файл конфигурации требует ФИО в некоторых
  случаях, но формат payload для подписи в запросе не был задан.
- Подтвердить использование `client_event_id` как `attachments.owner_id` до
  создания серверной записи.
- Уточнить ответ на идентичную повторную отправку (`200` с прежним результатом
  или `409`), затем обновить `docs/05-api/openapi.yaml` аддитивно.
